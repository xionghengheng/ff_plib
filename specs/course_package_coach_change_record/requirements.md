# 课包更换教练操作记录需求

## 范围

作为上一项课包历史记录功能的同类扩展，沿用其模型、表和 DAO 方案。按用户此前要求直接实现，不改动现有 handler 或课包更新接口。

## 验收标准

1. 当业务层保存更换教练操作时，系统应独立新增记录，保存 UID、课包 ID、原教练 ID、新教练 ID、操作时间、操作人、备注和创建时间，不覆盖历史。
2. 当查询记录时，系统应仅提供全量列表，按 change_coach_ts DESC、id DESC 游标分页；首页传 (0, 0)，后续传上一页最后一条的 ChangeCoachTs、ID，不使用 OFFSET。
3. 当访问数据库时，新增应使用 Create，查询应使用参数化 Raw SQL；字段有效性、鉴权、课包归属、教练存在性及重复操作由业务层处理。
4. 当交付时，系统应提供 model、DAO 接口与实现、含索引的建表 SQL；不直接执行数据库变更，不提供更新或删除历史的接口。
